## Задача

Начнём с примера. Посты автора А обычно получают около 20 реакций. Пост с 80
реакциями получил в четыре раза больше обычного, поэтому его класс — **`above`**
(«выше обычного»). Посты автора Б обычно получают около 300 реакций. Те же 80
реакций — примерно четверть его обычного результата, поэтому для него класс —
**`below`** («ниже обычного»). Метка показывает результат поста относительно
обычного результата его автора, а не абсолютное число реакций. Если дать модели
только абсолютные числа, она научится распознавать автора и сможет вовсе не
читать пост.

Расчёт выполняется отдельно для каждого **собственного** поста автора:

1. Берутся все собственные посты этого автора, опубликованные **раньше**
   оцениваемого поста. Если их меньше пяти, метка пока не вычисляется.
2. Для каждого из этих предыдущих постов считается натуральный логарифм
   `ln(1 + число реакций)`. Медиана полученных значений — обычный уровень автора
   (`level`) на момент оцениваемого поста. Сам оцениваемый пост в медиану не входит.
3. Из `ln(1 + число реакций на оцениваемый пост)` вычитается `level`.
   Полученная разница называется остатком (`resid`); по ней назначается класс.

Например, если у пяти предыдущих постов было 10, 20, 20, 30 и 40 реакций,
то `level = ln(21)` — медиана их преобразованных значений. Для нового поста с
80 реакциями `resid = ln(81) − ln(21) ≈ 1.35`, поэтому его класс — `above`.

| класс | `label` | остаток (`resid`) | реакции относительно обычного результата автора | доля в тесте |
|---|:---:|---|---|---:|
| `below` — ниже обычного | 0 | < -0.549 | менее ×0.577 | 20.1 % |
| `typical` — обычно | 1 | между порогами | между порогами | 59.5 % |
| `above` — выше обычного | 2 | > 1.157 | более ×3.182 | 20.4 % |

Пороги соответствуют 20-му и 80-му процентилям остатков в обучающей выборке и
без изменений применяются к тестовой. У первых пяти собственных постов автора
нет меток: они нужны для вычисления первого уровня. Меток также нет у обычных
репостов, для которых используются счётчики исходной публикации.
`python -m kairos.label` заново вычисляет все 89 018 меток по постам и сверяет их
с `labels.csv`.

**Разделение данных.** 80 / 20 по авторам, случайное зерно 42: в обучающей
выборке 3 295 авторов и 71 395 размеченных постов, в тестовой — 824 автора и
17 623 поста. Все посты одного автора находятся в одной выборке, поскольку
метка определяется относительно этого автора. Обучайте модель на обучающей
выборке, а результаты сообщайте по тестовой.

**Метрики.** Основная метрика — macro-F1. Она придаёт одинаковый вес трём
классам: если всегда отвечать `typical`, получится 0.25, тогда как точность
(accuracy) составила бы 0.60. Также приводится квадратично взвешенная каппа
(QWK): классы упорядочены, поэтому назвать пост класса `below` постом класса
`above` — более серьёзная ошибка, чем назвать его `typical`.

## Как получить данные

1. **Запросите пароль** на [странице датасета](https://kairos-labs.ai/dataset/).
   Он придёт по электронной почте.
2. **Скачайте основной архив:** пять томов от `lab1_core.7z.001` до `.005`
   (50.5 ГБ). В нём находятся тексты, метки, манифест медиафайлов, изображения
   и PDF. Для базовой модели этого достаточно. Отдельный архив с видео
   (11 томов, 114.1 ГБ) содержит видеозаписи из постов.
3. **Сверьте** SHA-256 каждого тома со значением на странице датасета:
   ```
   certutil -hashfile lab1_core.7z.001 SHA256    # Windows
   sha256sum lab1_core.7z.*                      # Linux / macOS
   ```
4. **Распакуйте архив в `data/`** этого репозитория. 7-Zip запросит пароль и
   автоматически подхватит остальные тома:
   ```
   7z x lab1_core.7z.001 -odata
   ```
   На Windows используйте 7-Zip, на macOS — Keka, на Linux — `p7zip-full`.
   Архив с видео распаковывается в тот же каталог `data/media/`.

```
data/
├── authors/AUTHOR_xxxx.json    профиль каждого автора
├── posts/AUTHOR_xxxx.json      лента автора в исходном виде; urn — код поста
├── media/<ab>/<sha256>.<ext>   каждый медиафайл в одном экземпляре, имя — хеш содержимого
├── media/manifest.jsonl        соответствие файлов и постов
├── labels.csv                  author, post, split, label, class
└── split.json                  авторы обучающей и тестовой выборок, а также пороги
```

Если данные хранятся в другом месте, передайте каждому скрипту параметр
`--data <folder>`.

## Быстрый старт

```
git clone https://github.com/Danil482/kairos-dataset.git
cd kairos-dataset
pip install -r requirements.txt

python -m kairos.label     # пересчитать метки и сверить их с labels.csv
python baseline.py         # сравнить конфигурации признаков и алгоритмы обучения
python evaluate.py --predictions results/predictions/hist_gradient_boosting__baseline.csv
```

Таблицы сравнения записываются в `results/metrics/hist_gradient_boosting.csv` и
`results/metrics/logistic_regression.csv`. Каждая строка — конфигурация или
контрольная стратегия; столбцы: `name`, `macro_f1`, `f1_below`, `f1_typical`,
`f1_above`, `qwk`, `accuracy`.

Строки `text_tf_idf`, `text_tf_idf_truncatedsvd` и
`text_multilingual_e5_small` добавляют к базовым признакам одно представление
всего текста поста. TF-IDF учитывает слова и пары слов; словарь ограничен
1 024 признаками. Вариант с TruncatedSVD сжимает те же векторы TF-IDF до 128
чисел. Вариант E5 использует `intfloat/multilingual-e5-small` (384 числа):
текст после 512 токенов модели отбрасывается. Преобразования, которым нужен
корпус текстов, обучаются только на обучающей выборке. При первом запуске
модель E5 скачивается; готовые эмбеддинги сохраняются в `results/`.

## Базовая модель

Градиентный бустинг использует всё из набора данных, кроме слов поста. Он
обучается на авторах из обучающей выборки со сбалансированными весами классов и
оценивается на 17 623 тестовых постах. Модель учитывает свойства поста (длину,
хештеги, упоминания, ссылки, тип, время публикации), сведения об авторе (его
обычный уровень и разброс реакций, частоту публикаций, число подписчиков) и
время сбора данных. Она не читает текст и не анализирует медиафайлы.

| | macro-F1 | QWK | точность (accuracy) |
|---|---:|---:|---:|
| **базовая модель** | **0.5410** | **0.4576** | **0.5465** |
| всегда `typical` | 0.2488 | 0.0000 | 0.5953 |
| случайный ответ с распределением классов обучающей выборки | 0.3319 | -0.0080 | 0.4386 |

Ориентир, который нужно превзойти, — **0.5410 по macro-F1**. Текст и медиа
остаются в вашем распоряжении.

### Для сравнения: Claude без обучения (zero-shot)

Какого результата может достичь передовая модель без обучения на датасете?
В октябре 2026 года Claude Opus 5.5 и Claude Sonnet 5.5 ответили на равномерно
случайную выборку из **2 000 тестовых постов** из 17 623 (630 из 824 тестовых
авторов). Приведённые числа относятся только к этим 2 000 постов: базовая
модель получает на них 0.5496, а не 0.5410. Сравнивайте результаты Claude с
этой строкой. Интервалы имеют доверительный уровень 95 % и получены повторной
выборкой авторов.

| на одних и тех же 2 000 тестовых постов | macro-F1 | QWK | точность (accuracy) |
|---|---:|---:|---:|
| базовая модель | 0.5496 [0.526, 0.572] | 0.4592 | 0.5575 |
| Claude Sonnet 5.5, без обучения, с пятью предыдущими постами автора | 0.5167 [0.491, 0.541] | 0.3787 | 0.6625 |
| Claude Opus 5.5, без обучения, с пятью предыдущими постами автора | 0.6272 [0.603, 0.650] | 0.5420 | 0.6870 |

Каждый пост обрабатывался отдельным вызовом `claude -p` (Claude Code, уровень
усилий `low`, без инструментов), поэтому модель не видела другие посты из
выборки. В запрос передавались обычное число реакций автора, пять его последних
предыдущих постов (первые 200 символов текста, число реакций и первое изображение
каждого), текст нового поста (до 1 000 символов) и до четырёх его изображений.
Видео представлялось кадром обложки. Модель спрашивали, получит ли пост заметно
меньше реакций, чем обычно (менее примерно ×0.58), примерно столько же или
заметно больше (свыше примерно ×3.2). Класс определялся выбранной моделью
буквой; никакой настройки не проводилось. Sonnet редко выбирает крайние классы
(7 % и 9 % ответов против примерно 20 % у каждого из них в разметке). Поэтому
его точность высока, а macro-F1 — низка.

Для этих сравнительных запусков авторы датасета по своему решению отправили
тексты и изображения постов в Anthropic. Это не меняет
[правила использования](#правила-использования): ваша копия медиафайлов должна
оставаться в пределах вашего курса и не передаваться внешнему сервису.

## Оценка своей модели

Запишите для каждого тестового поста отдельную строку с `author`, `post` и
предсказанным `label` (0, 1, 2) либо `class` (`below`, `typical`, `above`):

```
author,post,label
AUTHOR_xxxx,POST_xxxxxx,1
```

```
python evaluate.py --predictions my_predictions.csv
```

Скрипт выводит macro-F1, QWK, точность, F1 для каждого класса и матрицу ошибок.
Если в файле отсутствует хотя бы один тестовый пост, скрипт его отклонит.
Предсказания базовой модели в
`results/predictions/hist_gradient_boosting__baseline.csv` имеют тот же формат.

## Работа с данными

```python
from kairos.data import load_labels, load_posts
from kairos.label import author_level

posts = author_level(load_posts())     # собственные посты, уровень автора и остаток
table = load_labels().merge(posts, on=["author", "post"])
train, test = table[table.split == "train"], table[table.split == "test"]
```

На что легко не обратить внимание:

- **Даты.** `postedAt` в посте — относительная строка интерфейса LinkedIn
  (например, «2yr» или «1mo»). Точная дата — `postedDateTimestamp`, число
  миллисекунд с начала эпохи Unix. Поле `crawledAt` в начале файла ленты
  показывает время её сбора.
- **Число реакций — один снимок**, сделанный во время сбора данных. Медианный
  промежуток между публикацией поста и сбором данных составляет 710 дней.
- **Репосты.** Если `author.code` поста не совпадает с владельцем ленты или пост
  содержит блок `company`, это чужая публикация, которую автор перепостил вместе
  с исходными счётчиками. `load_posts(own_only=False)` возвращает всю ленту с
  флагом `own`. Публикация через диалог «Поделиться» в LinkedIn считается
  собственным постом автора и получает метку.
- **Замены в тексте.** Люди, организации, имена пользователей, адреса
  электронной почты, телефоны и ссылки заменены на `⟨PERSON_n⟩`, `⟨ORG_n⟩`,
  `⟨AUTHOR_n⟩`, `⟨HANDLE⟩`, `⟨EMAIL⟩`, `⟨PHONE⟩` и `⟨URL⟩`. Коды авторов и
  организаций едины для всего датасета; коды людей нумеруются отдельно в файлах
  каждого автора.
- **Медиафайлы.** `media/manifest.jsonl` связывает файлы с постами по полям
  `author` и `post`, а `from_reshared_post` отмечает файлы исходной
  перепощенной публикации. Видео не расшифрованы. У 1 332 постов в поле
  `document.transcript` есть текст прикреплённого документа, распознанный самим
  LinkedIn.
- **Подписчики.** Число подписчиков в `authors/*.json` было получено в 2026 году:
  это нынешняя аудитория, а не та, которая видела пост при публикации.

## Правила использования

Текст псевдонимизирован, а изображения, видео и PDF — нет. Лица, имена на
слайдах, логотипы и голоса в медиафайлах оставлены без изменений.

- **Не устанавливайте личности людей.** Не пытайтесь сопоставить код с реальным
  человеком и не публикуйте примеры, которые позволили бы сделать это другим.
- **Используйте данные только в рамках своего курса, проекта или исследования.**
  Не размещайте их повторно в открытом доступе и не передавайте пароль другим.
